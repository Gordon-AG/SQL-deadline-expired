# iBank SQL Tests — Selenide & Database Integration (ДЗ 3.2. SQL)

Автотесты для интернет-банка с интеграцией с базой данных MySQL: проверка формы авторизации, двухфакторной верификации (с чтением одноразового кода напрямую из БД) и работы со статусами пользователей через паттерн **Page Object** и утилиты `DbUtils`.

## Технологии

- **Java 11**, **JUnit 5**, **Gradle**
- **Selenide** — UI-тесты и автоматизация взаимодействия с браузером
- **Apache Commons DbUtils** — выполнение SQL-запросов и работа с базой данных
- **MySQL & Docker** — локальное хранение данных приложения
- **Lombok** — сокращение шаблонного кода (`@Value`)
- **JavaFaker** — генерация случайных тестовых данных

## Тестовые данные (в базе данных)

| Пользователь | Login | Password | Статус в БД |
|---|---|---|---|
| Первый | `vasya` | `qwerty123` | `active` / `blocked` |
| Второй | `petya` | `123qwerty` | `active` |

*Одноразовый код верификации динамически считывается тестом из таблицы `auth_codes` с помощью `DbUtils.getLastAuthCode()`.*

## Архитектура проекта (Page Objects & DbUtils)

### LoginPage
- `validLogin(AuthInfo)` — ввод валидного логина/пароля и переход к верификации
- `invalidLogin(AuthInfo)` — ввод неверных данных с проверкой уведомления об ошибке
- `assertBlocked()` — проверка появления текста блокировки

### VerificationPage
- `validVerify(VerificationCode)` — ввод одноразового кода из БД и переход на дашборд

### DashboardPage
- `shouldBeVisible()` — проверка успешного отображения главной страницы

### DbUtils (Взаимодействие с БД)
- `getLastAuthCode(login)` — получение последнего кода верификации (с retry-ожиданием)
- `getUserStatus(login)` — получение текущего статуса пользователя из таблицы `users`
- `blockUser(login)` — ручная установка статуса `blocked` для проверки реакции интерфейса
- `cleanTables()` — очистка временных таблиц (`auth_codes`, `card_transactions`) и сброс статусов перед каждым тестом

## Сценарии тестов (`LoginTest`)

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Успешный вход с кодом из БД | Код успешно вычитывается из базы, вводится, открывается `DashboardPage` |
| 2 | Проверка статуса после неверных попыток | После 3 неверных входов статус пользователя в БД остается `active` ( SUT не реализует автоблокировку «из коробки» ) |
| 3 | Обработка неверного пароля | Корректно отображается всплывающее уведомление об ошибке |

## Локальный запуск

Скопируйте и выполните команды из **единого блока** ниже:

```bash
# 1. Запуск контейнера с базой данных MySQL
docker compose up -d
```
```bash
# 2. Запуск тестируемого сервиса (SUT) из папки artifacts (порт 9999)
java -jar artifacts/app-deadline.jar
```
```bash
# 3. Запуск автотестов через Gradle в headless-режиме
./gradlew test -Dselenide.headless=true
```
